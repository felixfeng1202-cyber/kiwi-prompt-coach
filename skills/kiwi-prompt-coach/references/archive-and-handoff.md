# 交付与人工核验

交付前先完整执行 `final-compile.md`。然后按产物类型选择分支。

## Skill 模式

先用一小段话报告：创建或更新了哪个 Skill、落地位置、自动验证结果和未验证项。随后必须输出以下卡片，默认控制在一屏内。

```markdown
### [skill-name] 人工核验卡
- [ ] **能力**：一句话说明它能完成什么。
- [ ] **触发边界**：什么请求会触发；什么相似请求不应触发。
- [ ] **输入 → 输出**：需要什么信息、文件或状态；交付什么结果。
- [ ] **主流程**：用“1 → 2 → 3”写出必要工作逻辑，通常 3–6 步。
- [ ] **工具 / 依赖**：关键工具、数据、模板和外部系统；没有则写“无”。
- [ ] **权限 / 停止条件**：何时可自动继续，何时必须询问或停止。
- [ ] **自动验证**：列出已通过和未验证的结构、触发、行为或资源测试。
- [ ] **人工试跑**：给一个可直接复制的真实请求；写明应观察到的 2–3 个信号。
```

只有存在已知限制、兼容问题或未消除风险时，追加一行：

```markdown
- **已知风险**：[风险与影响]
```

卡片规则：

- 每项只写 1–2 个短句；主流程优先用箭头，不复述开发过程。
- 写具体能力和判断边界，不使用“功能完善”“符合预期”等空话。
- 自动验证与人工判断分开；未执行的测试不得写成已通过。
- 人工试跑应覆盖核心路径，不用边缘案例充数。
- 卡片用于快速核验，不写入目标 Skill，除非用户明确要求保存。

## Prompt 模式

1. 输出标注为“最终 Prompt”的已清理版本。
2. 简要说明适合放入聊天框、Project 指令还是其他目标位置。
3. 若用户需要团队反馈闭环，再输出精简归档信息：原始需求、关键改动、测试场景和剩余风险；默认不强制生成归档卡片。
