# Skill 模式

KIWI 在此模式中负责把业务需求编译为 Skill 合同，并联合 `$skill-creator` 端到端落地。不要停在“给用户一段 SKILL.md 草稿”，除非当前环境确实不能写入或用户只要求设计稿。

## 一、建立最小充分证据

优先从用户描述、现有 Skill 和真实使用记录中提取：

- 目标用户与反复发生的任务
- 应触发和不应触发的典型表达
- 输入、输出与完成标准
- 关键工作逻辑和顺序
- 需要的工具、数据、模板与权限
- 已知失败、异常与停止条件

信息足以安全实现就直接继续。缺少内容会实质改变能力边界时，只问最高杠杆的一项。

## 二、维护 Skill 合同

在内部维护以下合同；只有需要用户校准或有重要推断时才展示：

```markdown
## Skill 合同 - V1
- **目标能力**：
- **触发 / 不触发**：
- **输入 → 输出**：
- **核心流程**：
- **工具 / 依赖**：
- **权限与停止条件**：
- **成功标准**：
- **代表性测试**：
```

版本变化记录属于构建过程，不得写入最终 Skill。

## 三、联合 skill-creator 落地

1. 新 Skill 按 skill-creator 初始化；现有 Skill 先检查全部相关文件和已有修改。
2. 将内容放入最合适的层级：触发信息放 frontmatter；核心运行步骤放 `SKILL.md`；详细知识放 `references/`；稳定重复的确定性操作放 `scripts/`；输出素材放 `assets/`；界面信息放 `agents/openai.yaml`。编写 Skill 指令时应用 `prompt-writing.md` 的通用规则，避免提供商专属写法。
3. 只创建运行必需的文件。不要创建 README、变更日志或开发过程说明。
4. 使用可用的真实素材与模板，不把本轮对话内容硬编码为长期规则。
5. 实现后进入验证。

## 四、验证矩阵

按风险和复杂度缩放，但必须覆盖：

- **结构验证**：frontmatter、命名、引用路径和 `agents/openai.yaml` 有效。
- **触发验证**：至少有应该触发与不应触发的代表性表达。
- **行为验证**：用一个真实或最接近真实的任务检查主要输出和工作逻辑。
- **资源验证**：新增脚本实际运行；新增模板或资产能被正确找到和使用。
- **压缩验证**：最终 Skill 不含讨论记录、一次性补丁、重复规则和无用文件。

不能执行的验证必须标记为“未验证”并说明原因，不得推断为通过。

## 五、完成条件

同时满足以下条件才算完成：

1. Skill 已创建或更新到目标位置。
2. 必要的自动验证已通过，或未验证项已明确披露。
3. 已满足 `archive-and-handoff.md` 的 Skill 交付要求。
